# 05: Первый сквозной анализ батча из одного звонка

**What to build:** Заказчик загружает один звонок в выбранный стрим, команда вручную запускает его, а backend в фоне анализирует запись реальными сервисами и публикует подробный и сводный отчёты целиком.

**Blocked by:** 04 — Создание и выбор неизменяемого стрима.

Status: ready-for-human

- [x] API позволяет создать батч с идентификатором загрузки, принять аудио, завершить загрузку и получить статус. Пустой или незавершённый батч не запускается.
- [x] Только команда Vox AI запускает готовый батч; долгие модельные вызовы выполняются вне HTTP-запроса и транзакции БД. Статус и чтение API остаются доступны.
- [x] Обработка использует закреплённый контекст стрима и существующий порядок Whisper → роли → диалог/метрики → база знаний → оценка, с реальными запросами к моделям.
- [x] Реализовать согласованные опции и материалы обработки. При отключённом темпе критерий 2.2 получает 1 и пояснение; отключённые словарные опции не применяются.
- [x] Успешный результат содержит ровно 11 канонических критериев, оценки 0/0.5/1, бинарный 5.2, максимум 11, исходные оценки и пояснения. Неприменимость получает 1 с пояснением.
- [x] Нарушение определяется исходной оценкой 5.2=0. Включённый по умолчанию флаг обнуляет только итог; отключённый оставляет сумму. Противоречащий флаг LLM не определяет нарушение.
- [x] Все исходы, оценки, сводка и завершение публикуются одной атомарной фиксацией после обработки. До неё аналитических результатов в БД и доступного итогового отчёта нет.
- [x] Ошибка записи публикуется как исход завершённого батча; отсутствие успешных результатов даёт «нет данных» для средних и доли, а не нулевые оценки. Сбой всего батча или фиксации не публикует частичный отчёт.
- [x] После успешной фиксации удалить управляемые входы, сохранив метаданные, транскрипцию, оценки и материалы стрима; при ошибке всего батча входы сохранить.
- [x] Пройти малый живой сценарий через REST с реальными моделями и изолированными БД/файлами. Агрегаты сверить с фактическим результатом, а не заранее заданным ответом LLM.

## Comments

Первая вертикальная реализация включает минимальные необходимые хранение, фоновый запуск и отчётность. Устойчивое многобатчевое FIFO и восстановление развиваются отдельными задачами; атомарность публикации и правильные оценки обязательны уже здесь.

### Проверка 2026-10-07

Продолжены существующие незакоммиченные изменения, без переинициализации реализации.
Добавлены проверки отката при отказе второго исхода и завершения, отсутствия
сводки/времени завершения после отката, противоречащего флага LLM, отсутствующих
оценок/пояснений и отключённых метрик. Недоступный исполняемый ffprobe теперь
возвращает 503 `audio_probe_unavailable`, а не ошибку файла 422; временный файл удаляется.

Автоматические проверки: `unittest discover -s tests -v` — 20 прошли, 1 живой
пропущен; `unittest test_processing_context -v` — 3 прошли, 1 живой пропущен.
`compileall` и `git diff --check` прошли. Модели не подменялись.

Открытые критерии и конкретные причины:

- Приём настоящего аудио: API и идемпотентность реализованы, запреты пустого/
  незавершённого батча проверены, но успешный приём через ffprobe не подтверждён.
- Фоновый запуск/доступность API: отдельный worker и административный запуск
  реализованы; отсутствие HTTP/БД-транзакции вокруг моделей проверено по коду,
  но доступность во время настоящих модельных вызовов не проверена живым сценарием.
- Порядок обработки и реальные запросы: существующий pipeline сохранён;
  сквозной REST с настоящими Whisper/LLM в этой проверке не дошёл до моделей.
- Атомарность/ошибки: тесты подтвердили откат нескольких исходов, недоступность
  отчёта до завершения и `null` вместо нулевых средних; успешная публикация
  настоящего модельного результата ещё не подтверждена.
- Очистка: по коду выполняется только после commit; сохранение существующего
  входа при повреждении материалов стрима проверено. Проверка очистки исхода
  ошибки использует отсутствующий файл и не доказывает удаление существующего
  аудио после успешной публикации. Это должно подтвердить живое испытание.
- Живой REST: явный запуск `RUN_LIVE_BATCH_TEST=1` завершился FAIL на проверке
  `ffprobe unavailable; live acceptance blocked`, до REST и моделей.
  Фактическая настройка `VOX_FFPROBE_PATH` из окружения/.env — `ffprobe`,
  `shutil.which` возвращает None, файл по этому пути отсутствует; `where.exe`
  не находит ffprobe/ffmpeg. Поиск по дополнительным каталогам завершился
  тайм-аутом, поэтому отсутствие бинарника на всём диске не утверждается.
  Установки/загрузки не повторялись. Требуется предоставить рабочий абсолютный
  `VOX_FFPROBE_PATH` и повторить живой тест; критерии не закрыты фиктивным успехом.

Code-review выполнен по инструкциям репозитория и спецификации; исправлена
неверная классификация отсутствующего ffprobe. Внешние sub-agents недоступны,
ревью выполнено самим агентом. Восстановление processing и устойчивые повторы
очистки остаются задачами 08–10, без расширения области №05.
