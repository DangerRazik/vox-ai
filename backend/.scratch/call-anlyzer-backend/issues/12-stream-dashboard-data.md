# 12: Данные для дашбордов по стриму

**What to build:** Backend предоставляет данные для дашбордов по результатам обработки батчей одного стрима; frontend может отображать динамику и сопоставлять батчи без повторной обработки аудио.

**Blocked by:** 11 — Сравнение завершённых батчей одного стрима.

Status: ready-for-human
Implementation: completed
Resolution: completed

- [x] Предоставить через API историю опубликованных показателей батчей выбранного стрима из БД, а не из временных аудиофайлов или новых модельных ответов.
- [x] В ответе сохранить связь со стримом и идентификатором каждого батча, а также времени, нужные для упорядоченного отображения истории. Порядок и смысл времени явно описать в контракте.
- [x] Набор показателей совпадает с согласованной сводкой: счётчики, средний итог, средние критериев и критические нарушения. Не добавлять несогласованные рейтинги или объединённую оценку разных стримов.
- [x] Проверять принадлежность заказчику; не включать другие стримы, неопубликованные результаты и повторные технические попытки как независимые батчи.
- [x] Для пустой истории вернуть пустой набор; для батчей без успешных звонков сохранить «нет данных», не заменять нулями.
- [x] Данные согласуются с отчётами и сравнением, доступны после очистки аудио и рестарта. Запрос дашборда не вызывает модели.
- [x] Проверить API на нескольких батчах, подготовленных реальными моделями, и описать контракт для отдельного frontend-репозитория.

## Comments

Требование добавлено пользователем после подготовки исходной спецификации: дашборды строятся по результатам батчей в рамках одного стрима, данные берутся из БД с привязкой к стриму. Визуальные графики и интерфейс дашборда не реализуются в backend-репозитории. История показывает результаты батчей; она не подразумевает автоматически согласованных дополнительных метрик.
