# 01: Согласовать техническую основу backend

**What to build:** Подтверждённый технический проект тестового backend, по которому можно реализовать сквозную обработку батчей без молчаливого утверждения ранее предложенного стека.

**Blocked by:** None (can start immediately).

Status: ready-for-agent
Resolution: completed

- [x] Сопоставить существующий прототип и согласованные требования с предложениями по REST, общей локальной БД, очереди, отдельному worker и управляемому файловому хранению.
- [x] Представить пользователю конкретные технические решения и получить подтверждение; новые библиотеки не добавлять до согласования. Неподтверждённые решения не выдавать за принятые.
- [x] Зафиксировать подтверждённые решения, условия запуска, совместимость окружения и способ гарантировать один обрабатываемый звонок во всей системе.
- [x] Сохранить требования ADR о неизменяемых стримах, неприменимых критериях и атомарной публикации батча.
- [x] Определить подготовку изолированной живой проверки: доступные Whisper/LLM, операционные ключи, разрешённые тестовые записи и отдельные тестовые БД/каталоги. Секреты не публиковать.
- [x] Учесть, что реальные вызовы могут быть платными; выполнение большого тестового батча не является автоматическим следствием согласования стека.

## Comments

Подготовительная задача, а не отдельный инфраструктурный слой реализации. Завершение требует подтверждения пользователя, а не только написания документа.

Конфигурация сервисов заполнена, доступность не проверялась. До WAL требуется исправленный SQLite runtime; ffprobe не обнаружен через PATH. Код, зависимости и runtime не изменялись, модели не вызывались. Resolution фиксирует завершение отдельно от сохранённой роли triage в Status.
