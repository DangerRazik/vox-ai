# 06: Массовая API-загрузка с частичным приёмом

**What to build:** Заказчик формирует батч несколькими запросами; корректные записи обрабатываются независимо от ошибок отдельных файлов, а повтор загрузки не создаёт дубли.

**Blocked by:** 05 — Первый сквозной анализ батча из одного звонка.

Status: ready-for-human
Implementation: completed
Resolution: completed

- [x] Принять несколько файлов в один батч; одинаковое содержимое независимо от имени соответствует одной записи внутри этого батча.
- [x] Повтор исходного идентификатора загрузки возвращает тот же батч; изменение стрима или зафиксированного состава отклоняется. Новый идентификатор допускает отдельный анализ того же аудио.
- [x] Отказ одного файла не блокирует остальные. Ошибки загрузки видны отдельно и не увеличивают число принятых записей или ошибок обработки.
- [x] Employee ID и дата необязательны. Не вводить несогласованные продуктовые квоты или whitelist аудиорасширений; неподдерживаемое аудио получает объяснимый отказ.
- [x] Завершение разрешено при наличии принятой записи и фиксирует состав; последующее добавление/удаление записей запрещено. Повторы не увеличивают счётчики.
- [x] Ошибка обработки одной записи не прекращает обработку остальных; все исходы публикуются атомарно по окончании батча.
- [x] Сводка удовлетворяет равенству «принятые = успешные + ошибки обработки»; средние и доля нарушений используют только успешные результаты и исходные оценки критериев.
- [x] При отсутствии успешных записей публикуются ошибки и счётчики, средние/доля — «нет данных», число критических нарушений — 0.
- [x] Проверить смешанный приём, дедупликацию, повторы и многозаписный батч через API с реальными модельными вызовами там, где выполняется анализ.

### 2026-10-07 — реализация и проверки

Добавлены долговечные ошибки приёма, связь дубликатов с исходной записью,
`GET /v1/batches/{batch_id}/files` и отдельный `upload_errors` в статусе/сводке.
Завершение во время активной проверки файла возвращает `upload_in_progress`,
поэтому преждевременное закрытие состава исключено. История результатов
по-прежнему публикуется одной транзакцией по окончании обработки.

Проверки: 29 обычных тестов backend прошли, 3 opt-in сценария пропущены;

компиляции Python и `pip check` прошли. Публичные REST-тесты включают реальный
worker для двух ошибочных входов, без модельных вызовов.

исход и продолжил анализ второй через настоящие модели. Подробный результат
