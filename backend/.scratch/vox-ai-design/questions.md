# Оставшиеся вопросы для проектирования Vox AI

Статус: все семь групп вопросов отвечены пользователем 2026-10-06. Основные требования: [spec.md](spec.md). Ниже сохранён исходный список; принятые ответы приведены отдельно.

## Семь групп вопросов

1. **Входная директория.** Backend складывает в неё батчи, загруженные через API/UI, или нужен ещё самостоятельный способ вручную класть батчи в директорию? Рекомендация: использовать её как внутреннее место хранения загрузок API/UI.
2. **Удаление входных файлов.** Удаляем их после успешного сохранения результатов батча в БД? Что делать при ошибке батча? Рекомендация: очищать после фиксации результатов; ошибочные входные батчи сохранять до восстановления.
3. **Сведения о звонке.** Какие сведения поступают с записью: идентификатор сотрудника, дата звонка? Допустима запись без этих сведений? Рекомендация для теста: необязательные поля с сохранением имени файла; способ передачи в архиве описать в REST-контракте.
4. **Форматы и ограничения.** Какие аудиоформаты используются и известны ли предельные размеры файла/ZIP, количество записей и максимальная длительность звонка? Есть ли подпапки в ZIP? Рекомендация: числовые лимиты сделать настраиваемыми; ориентир 300 звонков не превращать в жёсткий предел. Возможности сервиса транскрибации определяются по реализации и его контракту.
5. **Выгрузка отчётов.** Достаточно данных через REST API или нужны CSV/XLSX/PDF? Рекомендация для теста: REST API, файловую выгрузку отложить.
6. **Дополнительное администрирование.** Нужны ли в первой версии отзыв/замена API-ключей и отключение старого стрима для новых загрузок? Рекомендация: выполнять эти операции вручную через административный API, сохраняя историю стримов.
7. **История результатов.** Как долго храним результаты, транскрипции и отчёты в общей БД? Рекомендация для теста: сохранять историю без автоматического удаления.

## Принятые ответы

| № | Решение пользователя |
| --- | --- |
| 1 | Директория — внутреннее место хранения загрузок API/UI. Самостоятельного канала ручного помещения батчей нет. |
| 2 | Входные файлы удаляются после успешной фиксации результатов в БД. При ошибке батча файлы сохраняются до восстановления. |
| 3 | Идентификатор сотрудника и дата звонка пока необязательны. |
| 4 | Продуктовых лимитов количества файлов, размера файла/архива, длительности звонка и whitelist аудиорасширений пока нет. Ранее согласованный ZIP без пароля сохраняется. |
| 5 | Достаточно REST API; CSV/XLSX/PDF-выгрузки в тестовую версию не входят. |
| 6 | Отзыв и замена API-ключей и отключение старых стримов для новых загрузок в тестовую версию не входят. |
| 7 | Автоматического удаления истории нет. Данные БД сохраняются до удаления стрима и удаляются вместе с ним. |

## Следующий результат работы

После ответов подготовить единый проект для проверки: модель данных, схему общей БД, архитектуру локального хранения и очереди, REST-контракты и примеры, обработку повторов и восстановление, предложения по технологическому стеку и критерии приёмки. Ночной режим остаётся за пределами тестовой версии. Алгоритмы внутри стрима принимаются из репозитория. Код до согласования проекта не писать.
