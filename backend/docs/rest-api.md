# Vox AI: предлагаемый REST-контракт v1

Статус: целевой проект контракта, 2026-10-06; реализация поэтапная.
Актуальное поведение стримов и автоподстановка настроек описаны в
[API стримов](stream-api.md).
Актуальное поведение реализованных батчей описано в [API-батчах](batch-api.md),
а ZIP-импорта №07 — в [контракте архивов](archive-api.md). Остальные операции
проверяйте по текущей реализации, этот перечень не подтверждает готовность
всего API. Связанные документы: [проект](backend-design.md), [модель](data-model.md),
[требования](../.scratch/vox-ai-design/spec.md).

## Общие правила

Префикс — `/v1`. JSON использует snake_case, идентификаторы ресурсов — UUID, даты — ISO 8601 с часовым поясом; серверные времена выдаются в UTC. Отсутствующий показатель — JSON `null`; оценки не заменяются нулём при отсутствии данных. Списки допускают cursor/limit для размера ответа; это не ограничение числа файлов загрузки.

Авторизация: `Authorization: Bearer <key>`. Ключ заказчика определяет организацию сервером. Административный ключ команды Vox AI имеет согласованные права на все организации. Клиент не передаёт `customer_id` для выбора владельца обычной загрузки.

| Код | Значение |
| --- | --- |
| 200 | Чтение, завершение загрузки или возврат уже существующего ресурса при повторе. |
| 201 | Создан новый ресурс/принята новая уникальная запись. |
| 202 | Принят первый ручной запуск батча в очередь. |
| 204 | Удаление стрима завершено в БД. |
| 401 | Ключ отсутствует или не распознан. |
| 403 | Для операции нужен административный ключ. |
| 404 | Ресурс отсутствует или не принадлежит организации заказчика. |
| 409 | Конфликт идентификатора/состава/состояния, ресурс занят, отчёт ещё недоступен. |
| 422 | Неправильная структура запроса либо файл не может быть принят. |

Пример ошибки:

```json
{"error":{"code":"batch_not_ready","message":"Загрузка батча не завершена","details":{}}}
```

Отказ конкретного файла возвращает ошибку и сохраняет запись ошибки загрузки, если файл полностью принят транспортом и идентифицирован. Остальные файлы батча продолжают приниматься. Повтор того же логического файла не увеличивает счётчик. Обрыв транспорта оставляет незавершённый приём, а не фиктивно обработанный звонок.

## Машинные статусы

| Значение | Согласованное название |
| --- | --- |
| `uploading` | Загружается |
| `ready` | Готов к запуску |
| `queued` | В очереди |
| `processing` | Обрабатывается |
| `completed` | Завершён |
| `upload_failed` | Ошибка загрузки |
| `batch_failed` | Ошибка обработки батча |

## Операции заказчика

Чтение этих ресурсов также доступно команде Vox AI. Для административного чтения списков допускаются явные фильтры `customer_id`; заказчик таким фильтром не расширяет свои права.

| Метод и путь | Назначение |
| --- | --- |
| `GET /streams` | Готовые стримы организации: ID, имя, дата создания, названия 11 критериев и публичные опции. |
| `GET /streams/{stream_id}` | Публичные сведения одного стрима. Полные промпты и материалы — через административный API. |
| `POST /batches` | Создание API-батча или возврат исходного по `upload_id`. |
| `POST /batches/{batch_id}/files` | Один аудиофайл за запрос; несколько запросов формируют массовую загрузку. |
| `POST /batches/{batch_id}/complete` | Явное завершение API-загрузки и фиксация состава. |
| `POST /batch-archives` | ZIP через UI; импорт и автоматическое завершение загрузки при наличии принятых записей. |
| `GET /batches` | Батчи организации; фильтры `stream_id`, `status`. |
| `GET /batches/{batch_id}` | Статус, входные счётчики, служебные времена и причина ошибки всего батча. |
| `GET /batches/{batch_id}/files` | Имена и исходы приёма, ошибки загрузки и связи дубликатов с записями. |
| `GET /batches/{batch_id}/calls` | Метаданные принятых записей; аналитический исход включён только после commit батча. |
| `GET /calls/{call_id}/report` | Подробный отчёт записи завершённого батча; для неуспешной записи — сведения об ошибке обработки без оценок. |
| `GET /batches/{batch_id}/report` | Итоговый сводный отчёт завершённого батча. |
| `POST /streams/{stream_id}/comparisons` | Показатели выбранных завершённых батчей этого стрима. Операция чтения, не новый анализ. |
| `GET /streams/{stream_id}/dashboard` | История опубликованных показателей батчей одного стрима в порядке завершения обработки. |

### Создание и повтор API-загрузки

`POST /batches`, JSON:

```json
{"upload_id":"customer-upload-001","stream_id":"<stream_uuid>"}
```

Новая пара `(customer_id, upload_id)` создаёт батч и возвращает 201. Повтор с тем же стримом возвращает 200 с тем же `batch_id` и текущим статусом. Другой стрим с тем же идентификатором — `409 upload_conflict`. Содержимое никогда не используется как глобальная защита от самостоятельного нового анализа: новый `upload_id` создаёт новый батч.

### Добавление файлов

`POST /batches/{batch_id}/files`, multipart/form-data:

- `file` — обязательный аудиофайл;
- `external_employee_id` — необязательная строка;
- `called_at` — необязательная дата/время ISO 8601.

Имя берётся из multipart. Backend назначает внутренний путь, вычисляет SHA-256 и проверяет обнаруживаемые ошибки/наличие аудиопотока, без вызова Whisper. Whitelist аудиорасширений и продуктовых размеров нет. Ошибки, обнаруженные только на этапе транскрибации, относятся к обработке записи.

Уникальное содержимое возвращает 201 и `call_id`. Повтор того же содержимого внутри батча возвращает 200, прежний `call_id` и `duplicate=true`; метаданные принятой записи не перезаписываются. Если при повторе явно переданы противоречащие исходным метаданные, возвращается `409 metadata_conflict` без изменения записи.

При загрузке в состоянии `uploading` допускается добавление записей. После закрытия состава новые записи не принимаются. Для `batch_failed` первый восстановительный приём создаёт одно новое поколение для последней неуспешной попытки, повторы запросов его не сбрасывают. Каждый переданный исходный файл отмечается заново принятым в этом поколении, даже если возвращается прежний call_id. Неизвестное исходному составу содержимое — конфликт; полное восстановление завершается отдельной операцией complete. Необязательные метаданные при повторе можно опустить, сохранённые значения остаются.

### Завершение загрузки

`POST /batches/{batch_id}/complete`, без тела. Нужны хотя бы одна принятая уникальная запись и отсутствие незавершённых передач файлов. Состав закрывается, батч ready. Повтор для уже закрытого батча возвращает текущий статус и не запускает обработку.

Пустой батч — `409 empty_batch`, текущая загрузка остаётся открытой. При восстановлении `batch_failed` нужно повторно принять все исходные уникальные записи; состав и стрим должны совпасть. После этого исходный батч ready и ожидает ручного запуска. Неполная/изменённая восстановительная загрузка — 409.

### ZIP через UI

`POST /batch-archives`, multipart/form-data:

- `upload_id` — идентификатор, создаваемый frontend и сохраняемый при повторе;
- `stream_id` — выбранный стрим;
- `archive` — ZIP без пароля;
- `metadata_file` — необязательный JSON-файл метаданных по относительным путям элементов ZIP.

Пример необязательных метаданных:

```json
{"calls/001.wav":{"external_employee_id":"employee-17","called_at":"2026-10-06T09:00:00+03:00"}}
```

Обычные подпапки импортируются. Каталоги не считаются файлами звонков. Вложенные архивы не раскрываются как отдельные батчи; они проверяются как входные файлы и получают отказ, если не являются аудио. Пути элементов не позволяют записать файлы за пределами управляемого каталога. Метаданные передаются отдельной частью, а не требуют служебного файла внутри ZIP.

После завершения импорта возвращается батч и список ошибок загрузки. Хотя бы одна запись → ready, ноль записей/невозможность импорта → upload_failed. Повтор с тем же `upload_id` не создаёт новый батч. Для готового/ожидающего/работающего/завершённого батча возвращается существующее состояние без повторной обработки; изменение закрытого состава — конфликт.

Для восстановления `batch_failed` ZIP может быть заново упакован, но исходный набор уникальных аудиофайлов и стрим должны совпасть. Идентичность определяется составом по содержимому, а не байтами ZIP-контейнера. После полного повторного импорта батч ready. Неудачный первичный импорт без закрытого состава допускает повтор импорта с прежним идентификатором.

### Сводный отчёт

До `completed`: `409 report_not_available`. Пример успешного отчёта:

```json
{
  "batch_id":"<batch_uuid>",
  "stream_id":"<stream_uuid>",
  "total_calls":90,
  "successful_calls":80,
  "processing_errors":10,
  "upload_errors":10,
  "average_total":9.65,
  "max_total":11,
  "criterion_averages":{
    "1.1":0.95,"1.2":0.9,"2.1":0.9,"2.2":1.0,
    "2.3":0.85,"2.4":0.8,"3.1":0.85,"3.2":0.9,
    "4.1":0.95,"5.1":0.8,"5.2":0.98
  },
  "critical_violation_count":2,
  "critical_violation_rate":0.025,
  "processing_started_at":"2026-10-06T12:00:00Z",
  "processing_finished_at":"2026-10-06T14:00:00Z",
  "processing_duration_seconds":7200
}
```

Это иллюстрация структуры, не замер скорости. Средние оценки округлены до двух знаков, доля — отношение 2/80. В хранилище исходные оценки не округляются. При нуле успешных записей `average_total=null`, все 11 средних `null`, `critical_violation_count=0`, `critical_violation_rate=null`. Счётчики записей и ошибок остаются числами.

### Подробный отчёт звонка

Ответ связывает `call_id`, `batch_id`, `stream_id`, исходное имя и nullable employee/date с `status`. При успешном анализе `result` включает данные существующего формата: `scores` по 11 ID, `total`, `max_total=11`, `critical_violation`, объяснение, `sentiment`, стресс, этикет, `kb_check`, рекомендации, `_segments` и `_metrics`. При ошибке `result=null`, возвращается код и причина ошибки обработки.

Канонические `scores[id].score` — исходные оценки, сохранённые для анализа критериев. `critical_violation` вычисляется сервером как `scores["5.2"].score == 0`; отдельный противоречащий флаг LLM не определяет факт нарушения. Обнуление применяется к `total` при включённом флаге и этом факте. Подробный отчёт и сводные счётчики используют один канонический признак. Причина темпа при отключённой опции — «анализ темпа отключён», балл 1. Прототип, обнуляющий все оценки, требует согласованной адаптации с восстановлением исходных значений.

### Сравнение батчей

`POST /streams/{stream_id}/comparisons`, JSON:

```json
{"batch_ids":["<batch_a_uuid>","<batch_b_uuid>"]}
```

Реализовано в №11: все выбранные батчи должны быть завершены, принадлежать этому
стриму и быть доступны по ключу. Ответ — `stream_id` и `items`, массив сохранённых
сводных отчётов в порядке запроса. Повтор одного ID не удваивает батч; требуются
минимум два разных UUID, иначе 422. Чужой/удалённый ресурс — 404, иной стрим или
незавершённый батч — 409. Whisper/LLM не вызываются, `null` сохраняется.
Подробности и проверки: [API сравнения](comparison-api.md).

### Данные дашборда стрима

Реализовано в №12: `GET /streams/{stream_id}/dashboard` возвращает `stream_id`
и `items` с сохранёнными сводными отчётами завершённых батчей выбранного стрима.
Порядок — по `processing_finished_at` от раннего к позднему, затем по `batch_id`.
Чужой/удалённый стрим — 404, пустая история — `items: []`; `null` сохраняется.
Новые модельные запросы не выполняются. Времена, показатели и интеграция frontend
описаны в [API дашборда](dashboard-api.md).

## Административные операции

| Метод и путь | Назначение |
| --- | --- |
| `POST /admin/customers` | Создать организацию и выдать её ключ. JSON `{name}`; ответ содержит `customer_id` и ключ при создании. |
| `GET /admin/customers` | Список организаций. |
| `POST /admin/customers/{customer_id}/streams` | Создать новый неизменяемый стрим с материалами. |
| `GET /admin/streams/{stream_id}` | Полный снимок параметров и метаданные материалов, без сервисных секретов. |
| `POST /admin/batches/{batch_id}/start` | Поставить ready-батч в FIFO. |
| `GET /admin/calls/{call_id}/audio` | Прочитать имеющийся входной файл для проверки. После очистки — 404 `audio_removed`; транскрипция и отчёт остаются доступными. |
| `DELETE /admin/streams/{stream_id}` | Удалить стрим и принадлежащие ему данные/материалы. |

Полное создание стрима предлагается как multipart: JSON `config`, обязательный файл `knowledge_base`, файлы `text_corrections`/`unwanted_expressions`, обязательные при включённых соответствующих опциях. `config` содержит имя, промпт Whisper, промпт оценки, три чекбокса второго этапа и `zero_total_on_critical` (default true). Набор 11 критериев берётся из репозитория. Проверка материалов производится до создания готового стрима; первоначально ошибочные материалы не создают пригодный для запуска стрим.

Первый start ready-батча возвращает 202 и queued. Повтор для queued/processing/completed — 200 с текущим состоянием. uploading/upload_failed/batch_failed — 409; для batch_failed сначала нужен согласованный повтор входов. Новая попытка после восстановления получает новую позицию FIFO.

DELETE требует административного ключа. При активном приёме/обработке этого стрима предлагается 409 `resource_busy`. В остальных случаях связанные данные удаляются каскадно, его очередные задания удаляются, каталоги очищаются. Повтор DELETE уже отсутствующего стрима — 404. Данные других стримов остаются.

Редактирования параметров существующего стрима, отзыва/замены ключей, отключения старого стрима, удаления заказчика, пользовательского логина, CSV/XLSX/PDF-выгрузок и обратной связи сотруднику в контракте v1 нет.
