# Подтверждённая техническая основа Vox AI

Пользователь подтвердил решения 2026-10-06 в задаче №01. Это согласование будущей реализации, не свидетельство наличия работающего backend.

## Стек

- Python, существующий pipeline и HTTP-клиенты; сохранить CLI. Контекст стрима передавать явно, не переключая глобальные настройки между заказчиками.
- REST: FastAPI, Uvicorn, существующий Pydantic; python-multipart для файловых загрузок.
- Общая локальная SQLite через стандартный sqlite3, без ORM. API и worker работают на одном компьютере; БД и файлы находятся на локальном диске, не на сетевой файловой системе.
- Очередь в общей БД, отдельный последовательный worker. Redis, Celery и отдельный файловый сервис не требуются.
- Эксклюзивная OS-блокировка общего файла через filelock (не SoftFileLock) удерживается весь срок жизни worker. Второй worker не начинает обработку; pipeline не параллелится, API не выполняет анализ самостоятельно.
- Проверка аудиопотока и обнаруживаемых ошибок контейнера через ffprobe без моделей и перекодирования. Скрытая ошибка декодирования может выявиться при обработке.

Новые библиотеки согласованы, но в задаче №01 не устанавливаются. Точные версии проверяются и фиксируются при реализации. Согласование основы не утверждает автоматически все детали проектов модели данных и REST-контракта.

## Инварианты

Метаданные приёма и очередь сохраняются до анализа. Захват задания атомарен, FIFO соответствует времени принятия запуска. Долгие запросы к моделям выполняются вне транзакций. Все исходы звонков, оценки, сводка и завершение батча фиксируются одной транзакцией; до этого аналитические результаты находятся в памяти worker.

Worker захватывает блокировку до восстановления оставленных состояний. Перезапуск API не объявляет ошибочным батч работающего worker. При завершении worker блокировка освобождается ОС; прерванный неопубликованный батч требует восстановления и ручного запуска, не автоматического повторного анализа.

Сохраняются [ADR-0001](adr/0001-immutable-streams.md) о неизменяемых стримах, [ADR-0002](adr/0002-inapplicable-criteria-score-one.md) о балле 1 для неприменимости и [ADR-0003](adr/0003-publish-batch-results-atomically.md) об атомарной публикации и отдельной повторяемой очистке.

## Проверенное окружение и условия запуска

Инспекция 2026-10-06: Windows, Python 3.14.6 в проектной .venv, SQLite 3.50.4; httpx 0.28.1, openai 3.19.2, Pydantic 2.13.5, pydantic-settings 2.15.0. FastAPI, Uvicorn и python-multipart отсутствуют среди проверенных установленных пакетов. ffprobe не найден через PATH; наличие вне PATH не проверялось.

Текущая SQLite 3.50.4 не допускается для предложенного WAL. До запуска backend подготовить совместимый runtime с исправлением WAL-reset: SQLite 3.51.3 или новее либо исправленная ветка 3.50.7. Проверять фактическую sqlite3.sqlite_version, не только Python. Сам Python 3.14.6 не является блокером.

Условия запуска последующих задач:

1. Воспроизводимые версии согласованных зависимостей; ffprobe через PATH либо явный путь.
2. Общие абсолютные пути БД, файлового корня и блокировки для API и worker; доступные права чтения/записи. Входы батчей и материалы стримов разделены.
3. На каждом соединении SQLite включить foreign_keys, WAL и ограниченное ожидание занятости; транзакции короткие. Один worker не исключает конкурирующие записи API.
4. API и worker запускаются отдельными процессами из одного окружения. Исполняемые точки входа и конкретные команды добавляются при реализации; сейчас их нет.
5. Административные и сервисные секреты только в операционной конфигурации, не в Git, материалах стрима, отчётах и логах.

Пользователь разрешил использовать живые записи; повторное согласование самого разрешения не требуется. Имеющиеся call_001.mp3–call_004.mp3 — кандидаты малого сценария, ещё не проверенные на пригодность.

Поля конфигурации Whisper/LLM (адреса, модели, ключи) заполнены; значения не публикуются. Это не доказывает доступность сервисов или действительность ключей: реальная проверка предстоит после подготовки реализации.

Использовать отдельный временный корень с тестовой БД, блокировкой, материалами и копиями входных записей. Не удалять исходные записи проекта, рабочую БД или результаты прежних запусков. Обработка проверяется реальными Whisper/LLM без подмены ответов; сценарии без анализа не вызывают модели искусственно.

Сначала малый живой сценарий, затем проверки изоляции, транзакций, FIFO, рестартов и очистки. Вызовы могут быть платными. Разрешение на записи не запускает автоматически батч порядка 300 звонков: большой прогон требует отдельного подтверждения расхода ресурсов.

Задача №01 не вызывает модели, не отправляет записи и не меняет зависимости/runtime. Подготовительная задача завершена; условия запуска выполняются в последующих задачах.
