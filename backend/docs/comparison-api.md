# Сравнение завершённых батчей

Реализовано в backend-тикете №11. `POST /v1/streams/{stream_id}/comparisons`
читает опубликованные сводки из БД; нового анализа и сохранения сравнения нет.
Авторизация — `Authorization: Bearer <customer-key>` или административный ключ.
Ключ заказчика определяет организацию; `customer_id` в запросе отсутствует.

```json
{"batch_ids":["<batch_b_uuid>","<batch_a_uuid>","<batch_b_uuid>"]}
```

Требуются минимум два разных UUID. Повторы удаляются с сохранением первого
положения, верхнего продуктового лимита числа выбранных батчей нет. Лишние поля,
неверные UUID и недостаточная выборка получают 422 `invalid_request`.

Ответ 200 содержит `stream_id` и `items` — сводные отчёты в порядке выбора,
в данном примере B, A. Каждый элемент совпадает с ответом существующего
`GET /v1/batches/{batch_id}/report`: `batch_id`, `stream_id`, `total_calls`,
`successful_calls`, `processing_errors`, `upload_errors`, `average_total`,
`max_total=11`, `criterion_averages` по 11 исходным критериям,
`critical_violation_count`, `critical_violation_rate` и времена обработки.
Итог учитывает правило обнуления, средние критериев сохраняют исходные оценки.
Доля — число 0..1. Если успешных результатов нет, средние и доля остаются `null`,
а число нарушений равно 0; «Нет данных» отображает frontend.

Без действительного ключа — 401. Недоступный или удалённый стрим/батч —
404 `not_found`, в том числе при смешанной выборке собственных и чужих ID.
Все права проверяются перед проверкой состояний батчей, чтобы не раскрывать
состояние чужого ресурса. Другой доступный стрим — 409
`comparison_stream_mismatch`; отсутствие опубликованного отчёта — 409
`report_not_available`. Частичного успешного ответа нет.

Проверки и чтение отчётов выполняются в одном снимке SQLite: публикация или
удаление не разделяют выборку на разные состояния. Сравнение доступно после
перезапуска API и удаления исходного аудио. Администратор читает все организации,
но также сравнивает только батчи одного выбранного стрима.

## Подготовленный frontend

Контракт соответствует выбранному пути из соседнего `frontend/docs/integration.md`.
REST-адаптер сопоставит `items` с `ComparisonColumn.summary`; для метаданных
`ComparisonColumn.batch` используются уже полученные батчи выбранного стрима.
Названия критериев берутся из сведений стрима. `total_calls` соответствует
`acceptedCalls`; остальные поля сводки переводятся из snake_case в camelCase.
404/409 отображаются как ошибка выбора, ошибки транспорта — как ошибка запроса.
Frontend в этой задаче не изменяется.

## Проверки

```powershell
.\.venv-backend\Scripts\python.exe -m unittest tests.test_comparison_api -v
$env:RUN_LIVE_COMPARISON_TEST = '1'
.\.venv-backend\Scripts\python.exe -m unittest tests.test_live_comparison -v
Remove-Item Env:RUN_LIVE_COMPARISON_TEST
```

Обычные проверки используют публичный REST, временные SQLite/файлы, настоящий
ffprobe и отдельный worker. Для «Нет данных» вход удаляется до анализа;
ответы моделей не подменяются. Живая приёмка использует два маленьких батча
с `call_002.mp3`, `call_003.mp3` либо `VOX_LIVE_AUDIO`, `VOX_LIVE_AUDIO_SECOND`,
настоящие HTTP API/worker и настроенные Whisper/LLM. Свёртки сравниваются с
опубликованными сводными и подробными отчётами текущего запуска. После очистки
аудио worker останавливается, API перезапускается; сравнение и права проверяются
снова. API запускается с недоступными модельными URL, без подстановки ответов.
БД/файлы изолированы от рабочих данных; секреты не выводятся.
