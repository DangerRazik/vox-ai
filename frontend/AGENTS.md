# Vox AI frontend

## Рабочие материалы

- Задачи и спецификации — локальные Markdown-файлы в `.scratch/`; текущая спецификация — `.scratch/vox-ai-ui/spec.md`.
- Отдельные задачи реализации при необходимости создаются в `.scratch/<feature>/issues/<NN>-<slug>.md`.
- Стандартные метки triage: `needs-triage`, `needs-info`, `ready-for-agent`, `ready-for-human`, `wontfix`.
- Доменная терминология — `GLOSSARY.md`; существенные архитектурные решения — `docs/adr/`, создаваемые по мере принятия решений.
- Визуальное направление и требования к экранам — `docs/design/ui-concept.md`.

## Границы

- Это отдельный frontend-репозиторий. Приложение разрабатывается на последней стабильной Angular, взаимодействие с backend — REST API.
- Backend параллельно разрабатывает другой человек. В рамках frontend-задач не изменять его реализацию; вопросы интеграции фиксировать в `docs/integration.md`.
- Приложение использует только REST API; источники условных данных и демонстрационный режим удалены. Ошибки сервера отображаются пользователю.
- Бизнес-требования уже определены в соседнем backend-репозитории: `../backend/.scratch/vox-ai-design/spec.md` и `../backend/docs/adr/` (пути от корня этого репозитория).
- `../backend/docs/rest-api.md` — проект контракта, а не подтверждение работающих endpoints.
- Термины frontend должны соответствовать `../backend/GLOSSARY.md`; при изменении общего понятия сверять оба словаря.
- Сервер определяет права доступа, фиксирует результаты и рассчитывает оценки. Интерфейс отображает эти данные и объясняет состояния пользователю.
- Скриншоты — концептуальные референсы. Не переносить из них элементы просмотрщика, демонстрационное меню и условные показатели в рабочее приложение.
- Результаты проектирования через `grill-with-docs` оформлены skill `to-spec` в `.scratch/vox-ai-ui/spec.md` со статусом `ready-for-agent`. При реализации использовать эту спецификацию как основной документ; выполненные задачи отмечаются в `.scratch/vox-ai-ui/ticket-plan.md`.
- Пользователь запросил браузерные сценарии и отдельные проверки компонентов форм и отчёта. Проверять внешнее поведение, а не внутренние методы и структуру реализации.
