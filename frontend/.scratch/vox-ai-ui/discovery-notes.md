# Vox AI — frontend

Дата начала проектирования: 2026-10-06.

Это архив черновика обсуждения перед оформлением `to-spec`. Основной документ — [спецификация](spec.md); ссылки и формулировки ниже отражают состояние черновика на момент сохранения.

## Принятые решения

- Frontend развивается в отдельном Git-репозитории `C:\Users\Пользователь\Desktop\vox-ai-workspace\frontend`, связанном с `https://code.int.platform.tatar.ru/vox-ai/frontend/vox-ui.git`.
- Файлы приложения и его документация создаются в этом репозитории.
- Framework: Angular последней стабильной версии. Точная версия будет проверена перед инициализацией приложения и закреплена в зависимостях и lock-файле.
- Frontend взаимодействует с backend по REST API.
- Первая версия включает два раздела: интерфейс заказчика и административный интерфейс команды Vox AI. Подтверждено пользователем 2026-10-06.
- Интерфейс заказчика: выбор готового стрима, загрузка ZIP, просмотр статусов и ошибок загрузки, отчёты звонков и батчей, сравнение завершённых батчей одного стрима.
- Административный интерфейс: создание заказчиков и выдача ключей, настройка и создание стримов, ручной запуск батчей, просмотр отчётов всех заказчиков, удаление стрима с его историей.
- Права разделов следуют ранее согласованным полномочиям backend: заказчик работает по ключу своей организации, команда Vox AI — по административному ключу. Пользовательских учётных записей в тестовой версии нет.
- Для тестовой версии API-ключ сохраняется в браузере между посещениями: после обновления страницы и повторного открытия сайта вводить его заново не нужно. Пользователь выбрал второй вариант 2026-10-06. Действие «Выйти» удаляет ключ из браузера и очищает отображаемые данные текущего подключения; серверный ключ при этом не отзывается.
- Начинаем с проектирования пользовательских сценариев; реализация приложения ещё не начата.
- Требования к бизнес-процессу уже описаны в соседнем backend-репозитории: `../backend/.scratch/vox-ai-design/spec.md`; проект контракта REST API — `../backend/docs/rest-api.md`. Эти пути указаны относительно корня frontend-репозитория.
- Локальные задачи и спецификации ведём в `.scratch/`, инструкции — в `AGENTS.md`, доменную документацию — в `GLOSSARY.md` и `docs/adr/`. Файлы создаются по мере необходимости.
- Пользователь предоставил пять скриншотов и описание концепции. Принимаем их как визуальное направление и основу структуры экранов; точные размеры, оформление компонентов и условные данные не являются окончательными требованиями. См. [концепцию интерфейса](../../docs/design/ui-concept.md).
- Под «нашими стандартами» пользователь понимает согласованные требования Vox AI и общие правила качества интерфейса. Отдельный корпоративный дизайн-гайд не требуется. Подтверждено 2026-10-06.
- Первую версию экранов разрабатываем на демонстрационных данных, затем подключаем REST API. Демонстрационный режим явно обозначается; рабочий режим не подменяет ошибку API выдуманными результатами. Подтверждено 2026-10-06.
- Backend параллельно разрабатывает другой человек. Изменения приложения и документации frontend ведём в этом репозитории; реализацию backend не меняем в рамках этой работы.
- Демонстрационные данные и реальный API должны использовать общую модель данных frontend и отдельные источники данных. Переключение источника не должно требовать переписывания экранов. Это технический принцип реализации выбранного подхода.
- Наш подготовленный проект `../backend/docs/rest-api.md` используем как основу для frontend и параллельной разработки backend. Пользователь подтвердил выбор 2026-10-06. Это не означает, что API уже реализован; недостающие технические детали фиксируем в [плане интеграции](../../docs/integration.md).
- При оформлении `to-spec` пользователь дополнительно запросил отдельные проверки компонентов в дополнение к основным сценариям в браузере. Подтверждено 2026-10-06; записано в итоговой спецификации.

## Подготовленный план реализации

Все заданные пользователю вопросы текущего раунда отвечены. [План первой версии](../../docs/frontend-plan.md) собран для подтверждения общего понимания перед реализацией. Детали интеграции, требующие согласования с разработчиком backend, остаются в отдельном документе и не препятствуют разработке демонстрационного режима.
