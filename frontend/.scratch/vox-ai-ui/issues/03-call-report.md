- [x] Критерии имеют раскрываемые пояснения; значения 0, 0,5 и 1 отображаются корректно, критическое нарушение — по критерию 5.2.

- [x] Для ошибочной записи показывается причина без оценок; постоянный аудиоплеер не требуется.

Проверки входят в эту задачу; реализация backend и изменение бизнес-правил не входят.

## Реализация и проверка

Имя записи в отчёте батча открывает разбор через `BatchesSource.callReport`. Данные звонка используют те же исходные оценки и итог, что сводка. Компонент `CallGrades` отображает опубликованные оценки; их пересчёт в рабочем интерфейсе не выполняется. Факт нарушения отображается по `5.2 = 0`; правило стрима влияет только на итог и не переключается в отчёте.

Демо-примеры: `batch-04-call-1` — обычный разбор с датой; `batch-04-call-2` — обнуление итога с сохранением исходных баллов; `batch-04-call-3` — длинная транскрипция и отсутствующие дополнительные результаты; `batch-04-call-81` — ошибка без оценок. `support-06-call-2` показывает нарушение при выключенном обнулении: итог 10, факт учтён в сводке, анализ темпа отключён, соответствующей метрики нет.

Состояния чтения не сохраняют старые аналитические результаты на экране; известная организация и возврат остаются доступны после ошибки. Чужой, отсутствующий и неопубликованный звонки не раскрывают результаты. Отсутствующие метаданные и дополнительные блоки не заменяются условными значениями.
