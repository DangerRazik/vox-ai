# 14: Настоящая загрузка и восстановление через REST

**Status:** ready-for-agent

**Implementation:** complete

**Утверждено:** пользователем 2026-10-06.

**What to build:** Заказчик передаёт ZIP серверу, видит фактические результаты приёма и восстанавливает ошибочный батч без дублирования.

**Blocked by:** 12: REST-подключение по ключу: батчи и стримы; 05: Состояние и восстановление батча.

**Этап:** REST.

**User Stories:** 6–22, 71–72.

**Внешнее условие:** Готовы ZIP-приём, исходы файлов и восстановление; согласованы метаданные и получение состояния по идентификатору при обрыве запроса. Оно блокирует реальную интеграцию, но не задачи демонстрационного этапа.

- [x] Архив и необязательные метаданные отправляются по согласованному multipart-контракту; новая независимая загрузка получает новый идентификатор.
- [x] Повтор той же загрузки сохраняет идентификатор, включая обновление страницы и потерю ответа; после неопределённого исхода запрашивается фактическое состояние.
- [x] Серверные ошибки файлов, принятые записи и дубликаты отображаются раздельно, частичная загрузка не теряется.
- [x] Восстановление использует прежний идентификатор и стрим, серверный конфликт состава показан явно; успешное восстановление ожидает ручного запуска.
- [x] Ошибки формы сохраняют исправляемые значения; интерфейс не устанавливает новые продуктовые ограничения размера или количества.
- [x] Браузерные проверки на контролируемых ответах покрывают частичный приём, потерю ответа и восстановление; компонентные проверки формы остаются действующими.
- [x] На доступном backend проверены приём и восстановление тестового батча с отдельно разрешённым минимальным исправлением ZIP-восстановления; анализ не запускается frontend автоматически.

Проверки входят в эту задачу. Исключение утверждено пользователем 2026-10-08: исправить ZIP-восстановление в существующем POST /v1/batch-archives по [подготовленному предложению](../backend-zip-recovery-gap.md). Остальная реализация backend и изменение бизнес-правил не входят.
