# 04: Демонстрационная загрузка ZIP

**Status:** ready-for-agent

**Implementation:** complete (2026-10-06).

**Утверждено:** пользователем 2026-10-06.

**What to build:** Заказчик выбирает стрим и ZIP, проходит демонстрационный приём и видит новый батч и исходы загрузки.

**Blocked by:** 01: Демо-вход и список батчей.

**Этап:** Демонстрационная первая версия.

**User Stories:** 6–13, 22, 67–69.

- [x] Форма принимает выбранный стрим, ZIP без пароля и необязательный файл JSON-метаданных по выбранному проекту API.
- [x] Новая независимая загрузка получает новый идентификатор; повтор запроса той же загрузки не создаёт ещё один батч.
- [x] Локальная имитация явно обозначена: условный результат не выдаётся за реальный анализ выбранного архива.
- [x] Показаны принятые уникальные записи, дубликаты и ошибки конкретных файлов; частичная ошибка сохраняет успешный приём остальных.
- [x] Дубликаты не увеличивают число записей и ошибок; ноль принятых не создаёт готовый к запуску батч.
- [x] После успешного приёма батч появляется в списке и ожидает ручного запуска команды; заказчик не получает кнопку запуска.
- [x] Окно выбора не закрывается по таймеру, ошибки формы не сбрасывают исправляемый ввод.
- [x] Браузерная проверка проходит загрузку до нового батча; проверки компонента формы покрывают обязательные поля, необязательные метаданные и результаты частичного приёма.

Проверки входят в эту задачу; реализация backend и изменение бизнес-правил не входят.

## Реализация и проверка

Заказчик открывает загрузку из списка выбранного стрима. `ZipUploadForm` проверяет обязательные поля и необязательный JSON-объект по относительным путям с `external_employee_id` и `called_at`. Ошибки не сбрасывают выбранные файлы. Используется обычный выбор файлов браузера без таймера закрытия. Проверка содержимого ZIP, наличия пароля и аудиопотоков относится к настоящему серверному приёму; демо явно сообщает, что архив не распаковывается и файлы не отправляются.

`UploadsSource.upload` принимает ID загрузки и выбранные файлы. `DemoUploadsSource` сохраняет результат по ID и добавляет батч в общий демонстрационный список. Частичный сценарий содержит 2 принятых уникальных файла, 1 дубликат и 1 ошибку; полный — 2 принятых без ошибок; пустой — 0 принятых и статус `upload_failed`. Имена и исходы файлов условные и не изображают содержимое пользовательского ZIP. JSON проверяется локально, но не меняет условные записи. Настройки сценариев вынесены в отдельный `DemoIntakeControls`.

Сценарий потери подтверждения фиксирует приём до ошибки. Повтор с теми же файлами и ID возвращает прежний результат без второго батча. «Начать новую загрузку» очищает файлы и создаёт новый ID; одинаковый ZIP в двух независимых загрузках создаёт два батча. Новые батчи и результаты сохраняются в памяти до перезагрузки страницы. После приёма отображается ожидание ручного запуска; кнопки запуска у заказчика нет. Восстановление общей ошибки обработки относится к №05.

Добавлены 8 браузерных сценариев и 15 проверок компонентов формы и результата. Проверены обязательность и необязательность полей, исправление/удаление JSON с сохранением ZIP, календарные даты, частичный и пустой приём, повтор без дублирования, новые ID, контекст организации/стрима, отсутствие внешних запросов, узкий экран 390 px и клавиатурный выбор файла. Фокус переходит к результату или ошибке подтверждения, а новая загрузка возвращает его в форму.

Финальный полный набор: **31 браузерный сценарий** в Edge через Playwright и **30 проверок компонентов**. Typecheck и production-сборка проходят. Форма и результат просмотрены на desktop и мобильном экране.
