# 15: Настоящие административные операции через REST

**Status:** ready-for-agent

**Implementation:** complete

**Утверждено:** пользователем 2026-10-06.

**What to build:** Команда выполняет административные действия на настоящем backend через уже проверенные экраны.

**Blocked by:** 12: REST-подключение по ключу: батчи и стримы; 10: Новый стрим на основе старого и удаление; 11: Ручной запуск и отчёты всех организаций.

**Этап:** REST.

**User Stories:** 46–60, 71–72.

**Внешнее условие:** Готовы создание заказчика и ключа, полный просмотр и создание стрима, запуск батча и удаление; согласован способ передачи материалов при копировании. Оно блокирует реальную интеграцию, но не задачи демонстрационного этапа.

- [x] Создание заказчика возвращает настоящий ключ при создании; список организаций не выдаёт его повторно.
- [x] Полный снимок и создание стрима используют согласованные параметры и файлы, не показывают сервисные секреты.
- [x] Создание на основе стрима всегда даёт новый ID; материалы передаются только способом, подтверждённым контрактом.
- [x] Постановка в очередь и повтор запуска отображают фактическое состояние без второго задания; заказчик получает серверный отказ на административные операции.
- [x] Удаление требует подтверждения, обрабатывает запрет занятого ресурса и очищает связанные представления только после успешного ответа.
- [x] Отчёты разных организаций остаются доступны команде с явным контекстом, права не определяются только скрытием меню.
- [x] Браузерные проверки с контролируемыми ответами покрывают успехи, 403, конфликт запуска и отказ удаления; компонентные проверки форм и подтверждения сохраняются.
- [x] На доступном backend проверен согласованный административный сценарий на тестовых данных. Никакие изменения backend или сообщения его разработчику не выполняются этой задачей.

Проверки входят в эту задачу; реализация backend и изменение бизнес-правил не входят.

## Принятый контракт и реализация

Подключены рабочие административные маршруты к существующим экранам и REST-адаптерам.
Полная конфигурация включает отдельный промпт распределения ролей, два промпта
анализа, модели, язык и пороги. Whisper-промпт допускает пустое значение по API.
При копировании конфигурация переносится полностью, обязательные материалы
выбирают заново; обычный POST выдаёт новый ID. Промпты/словарные файлы проверяет сервер.

Повтор ручного запуска отправляет тот же batch_id и читает фактическое состояние.
Точный порядок FIFO не публикуется текущим API и не выводится как выдуманная очередь.
Удаление обрабатывает действующий 409 resource_busy; queued-задание по backend
можно удалить вместе со стримом. После 403/409 снимок остаётся доступен.
