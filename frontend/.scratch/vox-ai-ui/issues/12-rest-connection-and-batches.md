## Проверка готовности интеграции

2026-10-07 первоначально проверена прежняя локальная копия backend. После запроса пользователя выполнены `git fetch origin` и fast-forward до `6de5b1d` из GitLab (`origin/master`), без изменений реализации backend. Frontend-задачи №01 и №06 выполнены. В обновлённом backend есть FastAPI (`backend/api.py`), Bearer-авторизация, изоляция организаций и настоящие операции чтения. Старый `docs/rest-api.md` остаётся проектом полного API; реализованный контракт уточняют код и `docs/customer-api.md`, `docs/stream-api.md`, `docs/batch-api.md`.

Уже можно использовать:

- `GET /v1/streams`: `{items: [...]}`, публичные опции, `criteria` с `id`/`title`, ID организации, имя и дату стрима.
- `GET /v1/batches`: `{items: [...]}`, фильтры `stream_id`/`status`, ID организации, ID загрузки, статусы и `total_calls`.
- `GET /v1/customers/{customer_id}`: название своей организации при известном ID.
- Bearer-ключ, ответы 401/403/404 и `error.code/message/details`; сервер не позволяет расширить доступ заказчика чужим `customer_id`.

Фактические ответы списков теперь определены кодом. Основное недостающее звено — контекст входа: в приложении нет операции, возвращающей роль и организацию текущего ключа. Выводить владельца из непустого списка стримов/батчей нельзя: при первом входе оба могут быть пустыми.

До реализации адаптера нужны:

- Адрес API для разработки с префиксом версии и возможность запросов с адреса frontend.
- Согласованная операция подключения: организация и полномочия определяются сервером по Bearer-ключу, включая ответ на отклонённый ключ.
- Решение по пагинации: реализованные списки возвращаются целиком; `cursor`/`limit` и следующий cursor не реализованы. Frontend не должен изображать серверную пагинацию.
- Отображение названия загрузки и среднего балла: `BatchStore.get` не возвращает `name`/`filename`/`average_total`. Средний итог есть в отдельном отчёте завершённого батча; для списка нужны дополнительные серверные поля либо согласованный вариант отображения с отдельным чтением отчёта и идентификатором вместо названия.
- Доступный тестовый backend и возможность ввести тестовый ключ локально для обязательной проверки реального входа и чтения. Секреты в Markdown и Git не сохраняются.

В `create_app` нет CORS middleware; для разных адресов frontend/API требуется серверная настройка либо прокси. Это вопрос среды подключения, а не обязательный новый endpoint. Документация содержит команду запуска на `127.0.0.1:8000`, но работающий сервер по этому адресу не подтверждён. Окружение `.venv-backend` не перенесено через Git; доступные здесь Python не содержат FastAPI и остальных REST-зависимостей. Поэтому живой вход не проверен. Для чтения списков не нужны worker, Whisper, LLM или ffprobe.

Новые пути или схемы контекста входа не объявлены согласованными. Демонстрационное приложение продолжает работать. После согласования недостающих полей и среды выполняются браузерные проверки с контролируемыми HTTP-ответами и отдельные проверки формы подключения, затем реальная проверка на доступном сервере.
