**Status:** ready-for-agent

**Implementation:** complete — 2026-10-08; REST-отчёты, разборы и сравнение, проверки, живая приёмка и независимое ревью завершены.

**Утверждено:** пользователем 2026-10-06.

**What to build:** Руководитель открывает опубликованные серверные отчёты и сравнение вместо демонстрационных наборов.

**Blocked by:** 12: REST-подключение по ключу: батчи и стримы; 03: Подробный разбор звонка; 07: Сравнение завершённых батчей.

**Этап:** REST.

**User Stories:** 17, 23–45, 71–72.

**Внешнее условие:** Готовы подробные и сводные отчёты, списки звонков и сравнение; уточнены схемы ответов и отсутствие данных. Оно блокирует реальную интеграцию, но не задачи демонстрационного этапа.

- [x] Отчёт батча, звонки, разбор и сравнение получают данные реальным адаптером по выбранному контракту.
- [x] Отчёт до публикации показывает соответствующее состояние без выдуманных средних; null не становится нулём.
- [x] Исходные оценки, итог и канонический признак нарушения сохраняют серверную семантику без пересчёта или изменения опубликованного результата.
- [x] Транскрипция, метрики, база знаний, рекомендации и ошибки отображаются по фактическим доступным данным.
- [x] Сравнение соблюдает порядок и ограничения одного стрима, а серверные конфликты и отсутствие доступа объясняются пользователю.
- [x] Существующие браузерные сценарии и компонентные проверки выполняются на контролируемых ответах REST, включая отсутствие результатов и критическое нарушение.
- [x] На доступном backend проверен переход от батча к звонку и сравнение; Whisper и LLM не вызываются тестами frontend.

Проверки входят в эту задачу; реализация backend и изменение бизнес-правил не входят.

## Реализация и приёмка

Исходная точка ревью подтверждена пользователем: frontend «Завершил приёмку и
ревью frontend-тикета 12» (`a1220fb`). Серверные схемы сверены с работающим
backend, включая вложенные `options`, опубликованные сводки и исходы звонков
`successful`/`processing_error`. Подключены общие экраны через `ReportsSource`,
рабочие маршруты заказчика и команды, переходы из списка/отчёта/сравнения.

Пользователь разрешил отдельно подготовить два маленьких батча через настоящие
Whisper/LLM. Оба имеют успешный опубликованный результат. Затем frontend-проверка
запустила только API на этой отдельной БД с недоступными адресами моделей:
батч → разбор звонка → перезагрузка → сравнение в порядке выбора. Рабочая БД,
ключи и код backend не изменялись. Локальные материалы и ключи проверки находятся
в игнорируемой `.scratch/runtime/` и не включены в коммиты.

Полная регрессия: 61 проверка компонентов/источников, 111 обычных браузерных
сценариев, typecheck и production build — успешно. Живая приёмка отчётов выполнена
отдельно; стандартный прогон пропускает два opt-in live-сценария. После ревью
исправлен формат дробных чисел в деталях метрик и объединено преобразование ролей;
повторены 19 затронутых браузерных сценариев, три проверки компонентов, typecheck/build.

Приёмка и повторное независимое ревью завершены. Triage-метка сохраняется по
правилам трекера; факт выполнения записан отдельно. [Итоговый отчёт](../reviews/13-review.md).
