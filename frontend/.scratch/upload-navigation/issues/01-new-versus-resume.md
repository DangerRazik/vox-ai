# Новая загрузка отдельно от повтора и восстановления

Status: ready-for-agent
Implementation: complete

## Причина

Страница `/customer/upload` автоматически подхватывала последний черновик заказчика,
включая неудачный ZIP. Кнопка новой загрузки из списка показывала старую ошибку.

## Критерии

- [x] Кнопка «Загрузить ZIP» из списка открывает чистую форму с новым ID и выбранным стримом.
- [x] Обновление текущей формы сохраняет её ID, стрим и проверяет результат отправки на сервере.
- [x] Черновики разных загрузок изолированы; новая загрузка не удаляет предыдущую.
- [x] «Восстановить» открывает выбранный батч и повторяет импорт с его прежними ID, включая после открытия новой формы.
- [x] Проверить сценарии переходов в браузере и компоненты формы, выполнить сборку.

Backend, обработка аудио и название батчей не меняются.

Проверено: 72 компонентные проверки, 15 браузерных сценариев ZIP/REST-загрузки,
проверка типов и production-сборка. Браузер проверяет новую форму после отказа,
обновление страницы, две независимые отправки, повтор предыдущего батча через
«Восстановить» и сохранность старого черновика по его URL.
Проверки использовали контролируемые REST-ответы, постоянная БД и модели не задействованы.
